# معماری Backup و Restore

## هدف

افزودن پشتیبان‌گیری بدون تخریب داده‌های موجود.

## اصول

- دیتابیس اصلی هیچ‌گاه برای Backup تغییر نمی‌کند.
- عملیات Backup فقط یک Snapshot از فایل Room ایجاد می‌کند.
- Restore در نسخه بعدی با کنترل Schema و تایید کاربر اضافه می‌شود.
- Migrationهای Room حفظ می‌شوند و حذف دیتابیس ممنوع است.

## مسیر توسعه

1. Export دیتابیس
2. انتخاب فایل توسط کاربر
3. اعتبارسنجی نسخه Schema
4. Restore امن با Backup قبل از جایگزینی
5. ثبت Log عملیات
